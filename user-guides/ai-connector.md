# AI connector

Feeds can be created, changed, previewed and generated by an AI client such as
Claude, or by the reporting service, through the store's AI connector. This is
how the reporting service applies its suggestions: it reads your feeds and
orders, tries a change on a sample product, and applies it.

It uses the `UpturnStudio_Mcp` module, which is installed together with this
one. This guide covers what to switch on and what to expect. The full list of
tools is in the [tools reference](../docs/mcp-tools.md).

## What an AI client can do

| | Needs the edit switch? |
|---|---|
| See your feeds, mapping, schedule and last run status | No |
| See what a product would look like in a feed, or why it is left out | No |
| See Google attribute values, click-attributed orders and settings | No |
| Create, change, copy, delete and generate feeds | Yes |
| Change mapping rows | Yes |
| Set and remove Google attribute values per product | Yes |
| Change click capture and generation settings | Yes |

An AI client can never change the subscription key or the edit switch itself.

## 1. Connect the connector

Follow the connector's own setup, in `app/code/UpturnStudio/Mcp/README.md`:

1. Give the admin role that will connect the **AI Connector (MCP)** permission
   (System > Permissions > User Roles).
2. For a remote client, set the public base URL under Stores > Configuration >
   Advanced > AI Connector (MCP). A local `bin/magento mcp:serve` needs no
   URL.
3. Add the connector in the AI client, using your store's `/mcp` address.

## 2. Give the role the Google Feeds permissions

The connector acts as the admin who signed in, using that admin's own role. On
top of the connector permission, the role needs the Google Feeds permission
for each thing it should do (System > Permissions > User Roles > Role
Resources > Google Feeds > API and AI Connector):

| Permission | Allows |
|---|---|
| Read Feeds, Options and Item Previews | Listing feeds, reading one, options, previews |
| Create, Change and Delete Feeds; Run Generation | All feed edits, mapping edits and generation |
| Read and Write Google Attribute Values | Listing, setting and removing values per product |
| Read Click-Attributed Orders | Listing orders that came from an ad click |
| Read and Change Settings | Reading and changing the settings |

Use a dedicated role for the connection if you can, so it holds only what it
needs. A tool refused for permission names the permission that is missing.

## 3. Decide whether to allow edits

**Stores > Configuration > UpturnStudio > Google Feeds > AI Connector (MCP)**

| Setting | What it does |
|---|---|
| **Allow Tools That Change Data** | **No** (the default): an AI client can only read. **Yes**: it can also make the changes in the table above, within the connecting admin's permissions. |

Leave it on **No** until you want an AI client to make changes. Then turn it
on, and turn it off again when you are done if you prefer.

> **Read this before turning it on.** The connector's sign-in screen tells the
> admin that the client is asking for read-only access. With edits allowed
> that is no longer true for Google Feeds data. Make sure everyone who can
> connect an AI client knows.

## Checking what a change will do

An AI client can preview any change without saving it: the preview takes a
mapping and a SKU and returns the item as it would be written, or the reason
the product would not be listed. That lets a suggestion be checked on a few
products before it is applied to the whole feed.

Changes are applied immediately and are not versioned. If you want an AI client
to work cautiously, ask it to read the feed's current mapping first and keep a
copy of it before changing anything.

## What is recorded

The connector shows connected apps and lets you revoke them (System > AI
Connector (MCP)). Edits made through the tools change the feed and its
`updated_at` time like any other edit, but are not logged against the client
that made them.

## Headless storefronts

This is separate from the AI connector. A headless storefront that cannot send
Magento the click cookie can attach the Google Ads click to the cart through a
REST call or a GraphQL mutation instead. See [Ad click
tracking](ad-click-tracking.md) and the [REST reference](../docs/api.md).
